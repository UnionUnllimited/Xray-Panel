WEBSITE

Личный кабинет для клиентов с оплатой, управлением подпиской. Требует отдельный домен и проксирующий сервер.

📦 Минимальная версия бота: 3.4.5
🖥 Требует: VPS с Nginx
⏱ Время установки: ~20 минут

Требования

Сервер с ботом (основной) Ubuntu 24.04+ · Python 3.12 · Бот версии ≥ 3.4.5
Проксирующий сервер (отдельный VPS) Ubuntu 20.04+ · Nginx · Certbot · Открытые порты 80, 443
⚠️
Важно: WEBSITE нельзя разворачивать на одном сервере с ботом без прокси. Реальный IP бота должен быть скрыт — все запросы идут через проксирующий сервер.
ℹ️
Для домена необходимо создать A-запись, указывающую на IP проксирующего сервера (не на сервер с ботом).
2

Настройка почты

Почта используется для отправки кодов подтверждения при входе клиентов. Поддерживаются два варианта:

🔷 Resend API (рекомендуется) Работает через HTTPS, не требует открытых портов. Регистрация: resend.com

1. Создайте аккаунт
2. Подтвердите домен
3. Создайте API-ключ
4. Укажите RESEND_API_KEY и SMTP_FROM
📧 SMTP (резервный вариант) Работает если RESEND_API_KEY не задан. Требует SMTP-сервер (Gmail, Яндекс, свой).

Укажите: SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, SMTP_FROM
⚠️
Resend: Адрес отправителя SMTP_FROM должен быть на верифицированном домене. В тестовом режиме письма приходят только на ваш email.

Вход через Telegram (виджет)

Опционально. Добавляет кнопку «Войти через Telegram» на странице входа — пользователи могут авторизоваться без email.

Шаг 1 — Разрешить домен в BotFather

BotFather
/setdomain
→ выберите вашего бота
→ введите домен без https:// и без слэша в конце

Пример: cabinet.ваш-домен.ru
⚠️
Домен должен совпадать с доменом в SITE_URL. Поддомены считаются отдельными доменами — vpn.example.com и cabinet.example.com нужно добавлять отдельно.

Шаг 2 — Добавить переменную в .env (если нет)

env · /root/bot/.env 
# Имя бота без @ — обязательно для виджета
BOT_USERNAME=myvpnbot
✅
После сохранения .env и перезапуска сервиса (шаг 5) на странице /auth появится кнопка «Войти через Telegram». Токен бота подтягивается автоматически из БД — дополнительно настраивать не нужно.

Важно: Виджет работает только по HTTPS. На HTTP-адресах Telegram заблокирует его загрузку.

Systemd сервис

Создайте файл сервиса. Замените XX.XX.XX.XX на реальный IP вашего проксирующего сервера.

bash · Создание файла 
$ nano /etc/systemd/system/website.service
ini · /etc/systemd/system/website.service 
[Unit]
Description=VPN Website
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/bot/website
ExecStart=/root/bot/website/venv/bin/uvicorn run:app \
    --host 0.0.0.0 \
    --port 3012 \
    --log-level info \
    --proxy-headers \
    --forwarded-allow-ips=XX.XX.XX.XX
Restart=always
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
bash · Запуск и активация 
$ systemctl daemon-reload
$ systemctl enable website
$ systemctl start website
$ systemctl status website
⚠️
--forwarded-allow-ips должен содержать только IP вашего проксирующего сервера. Если указать * — любой может подделать свой IP через заголовок.

Настройка UFW (фаервол)

На сервере с ботом. Порт 3012 открываем только для проксирующего сервера.

bash · Сервер с ботом 
# Обязательно сначала — иначе потеряете SSH-доступ!
$ ufw allow 22/tcp

# Стандартные порты (нужны если на этом сервере есть другие сервисы)
$ ufw allow 80/tcp
$ ufw allow 443/tcp

# Порт сайта — только с IP проксирующего сервера
$ ufw allow from XX.XX.XX.XX to any port 3012

# Включаем фаервол
$ ufw --force enable
$ ufw status verbose
⚠️
Критично: Выполните ufw allow 22/tcp до ufw enable, иначе SSH-соединение оборвётся и доступ к серверу будет потерян.

Проксирующий сервер — Nginx + SSL

Выполняется на отдельном VPS (проксирующем сервере). Замените cabinet.ваш-домен.ru и IP-бота на реальные значения.

Установка Nginx и Certbot

bash · Проксирующий сервер 
$ apt update && apt install -y nginx certbot python3-certbot-nginx

Получение SSL-сертификата

Выберите один из двух способов:

Вариант А — через Nginx плагин Nginx не нужно останавливать. Certbot сам добавит временный location.
Вариант Б — standalone Нужно остановить Nginx перед командой и запустить после.
bash · Вариант А (рекомендуется) 
certbot --nginx -d cabinet.ваш-домен.ru
bash · Вариант Б (standalone) 
# Остановить Nginx перед получением сертификата
systemctl stop nginx

certbot certonly --standalone -d cabinet.ваш-домен.ru

# Запустить Nginx обратно
systemctl start nginx

Конфигурация сайта

Создайте файл на проксирующем сервере и вставьте конфигурацию ниже:

bash 
$ nano /etc/nginx/conf.d/website.conf
nginx · /etc/nginx/conf.d/website.conf 
server {
    listen 80;
    server_name cabinet.ваш-домен.ru;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name cabinet.ваш-домен.ru;

    ssl_certificate     /etc/letsencrypt/live/cabinet.ваш-домен.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/cabinet.ваш-домен.ru/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    location / {
        proxy_pass         http://IP-бота:3012;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto https;
        proxy_connect_timeout 10s;
        proxy_read_timeout    60s;
    }
}
bash · Применение конфигурации 
# Проверка конфигурации
$ nginx -t

# Применение без перезагрузки
$ systemctl reload nginx

# Или полный перезапуск
$ systemctl restart nginx

Настройка OAuth входа

Пошаговые инструкции для получения ключей Google и Яндекс. После получения ключей добавьте их в .env файл website.

Google OAuth

1
Открой Google Cloud Console
Перейди на console.cloud.google.com и войди через свой Google аккаунт.
2
Создай проект
Вверху слева нажми выпадающее меню с проектами → New Project → введи любое название (например VPN Bot) → Create.
3
Настрой OAuth consent screen
В левом меню: APIs & Services → OAuth consent screen
Выбери External → Create
Заполни обязательные поля:
  • App name — название твоего сервиса
  • User support email — твой email
  • Developer contact email — твой email
Нажми Save and Continue на всех шагах до конца → Back to Dashboard.
4
Опубликуй приложение
На странице OAuth consent screen найди раздел Publishing status → нажми Publish App → Confirm.
Без этого шага вход доступен только первым 100 тестовым пользователям.
5
Создай OAuth Client ID
В левом меню: APIs & Services → Credentials → + Create Credentials → OAuth client ID
Тип: Web application
В разделе Authorized redirect URIs добавь:
https://твойдомен/auth/google/callback
6
Скопируй ключи
После создания появится всплывающее окно с двумя значениями. Скопируй их в .env: 
GOOGLE_CLIENT_ID=123456789-abc...apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxxxxxxxxxxxxxxxx
ℹ️
Пользователи будут видеть экран «Это приложение не проверено Google» — это нормально для внутреннего сервиса. Достаточно нажать Дополнительные параметры → Перейти на сайт. Верификацию проходить не нужно.

Яндекс OAuth

1
Открой Яндекс OAuth
Перейди на oauth.yandex.ru и войди через свой Яндекс аккаунт.
2
Создай приложение
Нажми Создать приложение → введи любое название.
3
Выбери платформу и права
Платформы → поставь галочку Веб-сервисы
В поле Redirect URI добавь:
https://твойдомен/auth/yandex/callback

Права доступа → раскрой раздел Яндекс ID → включи:
  • login:email — доступ к email адресу
  • login:info — доступ к основной информации профиля
4
Сохрани и скопируй ключи
Нажми Создать приложение. На странице приложения найди ClientID и Client secret (Client secret откроется по кнопке). Скопируй в .env: 
YANDEX_CLIENT_ID=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
YANDEX_CLIENT_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
✅
После добавления ключей в .env перезапусти website: systemctl restart website.service — кнопки появятся на странице входа автоматически.
