Установка

Развёртывание бота на сервере

Пошаговое руководство: копирование файлов на VPS, получение SSL-сертификата и запуск всех сервисов через единый скрипт.

Ubuntu 24.04 Python 3.12 nginx systemd certbot
0

Требования

ОС
Ubuntu 24.04
Python 3.12 (включён по умолчанию)
Доступ
Root по SSH
порт 22 или кастомный
RAM / CPU
от 2 GB RAM, 2 vCPU
при использовании всех модулей (бот, админка, xuiweb, аналитика)
Домен
А-запись → IP сервера
нужен для SSL (Let's Encrypt)
1

Подключитесь к серверу по SSH

  • 1Скачайте и установите PuTTY: putty.org
  • 2В поле Host Name введите IP вашего сервера, порт 22, тип подключения SSH
  • 3Нажмите Open, введите логин root и пароль от сервера
2

Загрузите папку bot на сервер

⚠️
Папку нужно разместить точно по пути /root/bot. Скрипт установки проверяет текущую директорию и завершится с ошибкой, если запустить из другого места.
Через WinSCP / FileZilla (графический интерфейс)
  • 1Откройте WinSCP или FileZilla, подключитесь к серверу (протокол SFTP, порт 22)
  • 2В правой панели (сервер) откройте папку /root/
  • 3Перетащите папку bot из левой панели (ваш ПК) в правую — на сервер
  • 4Дождитесь завершения копирования
ℹ️
После загрузки проверьте, что структура выглядит так: /root/bot/install_bot.sh, /root/bot/service/, /root/bot/web_admin/ и т.д.
3

Запустите скрипт установки

bash 
cd /root/bot
bash install_bot.sh
⚠️
Скрипт требует root-прав и запуска строго из /root/bot/. Не используйте sudo bash install_bot.sh из другой директории.
4

Что скрипт спросит в процессе

Скрипт автоматически устанавливает зависимости и задаёт несколько вопросов. Ниже — каждый из них.

🔐 Секретный путь веб-админки Рекомендуется задать
Веб-админка будет доступна по адресу https://домен/путь/.
По умолчанию предлагается admin123 — смените на что-то уникальное, это защита от перебора.

Сгенерировать путь: —
🌐 Домен для SSL-сертификата Обязательно
Введите домен, А-запись которого уже указывает на IP этого сервера.
Скрипт автоматически получит сертификат через Let's Encrypt и настроит nginx.
Пример: bot.example.com
⚠️
Если А-запись ещё не указывает на сервер — сначала настройте DNS, подождите распространения (до 24ч), затем запускайте установку.
🤖 Токен Telegram-бота Рекомендуется задать
Токен бота из @BotFather в Telegram.
Если пропустить (Enter) — сервис запустится, но бот работать не будет и может создавать лишнюю нагрузку на сервер. Токен можно задать позже в веб-админке.
Формат: 1234567890:ABCDEFabcdef...
📡 Установка SUBPAGE (страницы подписки) На выбор
Вариант 1 — установить SUBPAGE на этот же сервер. Скрипт скопирует папку /root/bot/subpage в /root/subpage и запустит его установку. URL подписки будет на том же домене.

Вариант 2 — SUBPAGE находится на внешнем сервере. Скрипт спросит его домен (по умолчанию подставит ранее введённый домен бота). URL подписки будет сохранён в базе данных.

Что скрипт делает автоматически

  • ✓Устанавливает Python 3, pip, sqlite3, nginx, certbot
  • ✓Получает SSL-сертификат через Let's Encrypt и копирует в /root/cert/
  • ✓Генерирует конфиг nginx /etc/nginx/conf.d/xuiweb.conf с вашим доменом и секретным путём
  • ✓Создаёт виртуальные окружения Python (venv) и устанавливает зависимости для бота, веб-админки, xuiweb и аналитики
  • ✓Записывает домен и секретный путь в базу данных /root/bot/vpn_bot.db
  • ✓Копирует .service-файлы в systemd и запускает сервисы:
    vpn-bot, vpn-webadmin, xuiweb, analytics
  • ✓Добавляет все сервисы в автозапуск при перезагрузке сервера

Частые проблемы

certbot не получает сертификат

А-запись домена не указывает на IP сервера, или порт 80 занят другим процессом. Скрипт останавливает nginx перед certbot — убедитесь, что порт 80 свободен.

Скрипт завершается с ошибкой «не в /root/bot»

Убедитесь, что папка скопирована именно в /root/bot, а не в /root/bot/bot. Проверьте: ls /root/bot/install_bot.sh

Сервис запущен, но бот не отвечает

Скорее всего, не введён токен бота. Откройте веб-админку → Настройки → Основные → укажите токен и сохраните. Затем перезапустите: systemctl restart vpn-bot

pip install зависает или падает
# Проверьте доступность PyPI
curl -I https://pypi.org
# Попробуйте запустить установку повторно
bash install_bot.sh
Внешний сервер

SUBPAGE — страница подписки

Отдельный веб-сервер для страницы подписки пользователей. Рекомендуется размещать на независимом сервере с собственным доменом.

Ubuntu 24.04 Python 3.12 nginx + SSL systemd
⚠️
Рекомендация по домену. Настоятельно рекомендуется использовать отдельный домен для SUBPAGE, не связанный с доменом бота. Например, если бот на bot.example.com, для SUBPAGE возьмите другой домен. Это повышает безопасность и позволяет независимо управлять подписками.
1

Подготовка сервера

  • ✓Сервер с Ubuntu 24.04, доступ root по SSH
  • ✓Отдельный домен с А-записью, указывающей на IP этого сервера
    Пример: sub.example.com
  • ✓Порты 80 и 443 открыты в файрволе
2

Установка SUBPAGE

Выполните команду на сервере SUBPAGE (не на сервере бота):

bash 
bash <(curl -sSL https://update.3xstore.ru/subpage/install.sh)
Скрипт автоматически
  • ✓Установит Python 3.12 и необходимые зависимости
  • ✓Создаст виртуальное окружение и установит пакеты
  • ✓Создаст systemd-сервис для автозапуска
  • ✓Установит CLI-утилиту управления subpage
3

Настройка Nginx и SSL-сертификата

После установки запустите CLI-утилиту управления:

bash 
sudo subpage
  • 1В главном меню выберите 9 — 🌐 Управление Nginx
  • 2В подменю выберите 1 — 🌐 Установить и настроить Nginx с SSL
  • 3Введите домен SUBPAGE: например sub.example.com
  • 4Укажите email для Let's Encrypt — желательно ввести, чтобы получать уведомления об истечении сертификата
  • 5Скрипт получит сертификат через Certbot и настроит nginx как reverse proxy
💡
Certbot использует standalone-режим. Убедитесь, что порт 80 свободен. Если нужно открыть порты — в главном меню выберите пункт 8 — 🔥 Управление файрволом.
4

Настройка файрвола (UFW)

bash 
sudo ufw allow 22/tcp  comment 'SSH'
sudo ufw allow 80/tcp  comment 'HTTP (Nginx)'
sudo ufw allow 443/tcp comment 'HTTPS (Nginx)'
sudo ufw enable
5

Настройка переменных окружения (.env)

Запустите CLI и выберите 6 — 📝 Редактировать .env файл:

bash 
sudo subpage
Обязательно указать

В .env на сервере SUBPAGE достаточно задать две переменные. Остальные параметры в файле — опциональны: они используются как запасной вариант, если API бота недоступен (ошибка сети, таймаут, 404) или если API_CUSTOM_SETTINGS=false.

.env 
# URL API бота (откуда subpage берёт данные подписки)
# SUBPAGE на отдельном сервере:
API_BASE_URL=https://bot.domain.com
# SUBPAGE на том же сервере, что и бот:
# API_BASE_URL=http://127.0.0.1:8282

# true — настройки страницы из веб-админки (Настройки → SUBPAGE)
API_CUSTOM_SETTINGS=true
ℹ️
API_CUSTOM_SETTINGS=true — при старте subpage один раз запрашивает {API_BASE_URL}/api/settings/info и подставляет значения из раздела Настройки → SUBPAGE (название, ссылки, тема, заглушки и т.д.). После изменений в админке нужен перезапуск subpage — иначе останутся старые значения.

Поля в .env (PROJECT_NAME, SUPPORT_URL, ссылки на приложения и др.) при успешной загрузке из админки переопределяются только там, где в админке задано непустое значение; при недоступности API subpage продолжит работать по .env.

В редакторе nano: Ctrl+O — сохранить, Enter — подтвердить, Ctrl+X — выйти. Полный список переменных — в subpage/env.example.

После сохранения .env перезапустите сервис:

bash 
sudo systemctl restart subpage
