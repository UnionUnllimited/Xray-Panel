# Xray-Panel — бот подписок под Remnawave 2.7.4

Telegram-бот для продажи подписок с веб-админкой (PWA) поверх панели
**Remnawave 2.7.4**. Основа — бот RM-Only 1.0 (3XUIStore), логика 3X-UI в нём
уже вырезана. PWA админки обновлена до v3.11.285.

Корень репозитория — это папка `/root/bot` на сервере: установщик работает
только оттуда.

| Сервис (systemd) | Что делает | Где слушает |
|---|---|---|
| `vpn-bot` | бот (`main.py`), вебхуки оплат и Remnawave | `127.0.0.1:8081` |
| `vpn-webadmin` | веб-админка + PWA (`web_admin/`) | `127.0.0.1:8181` |
| `xuiweb` | API подписки для бота и страницы подписки | `127.0.0.1:8282` |
| `subpage` (по желанию) | страница подписки `/sub/<uuid>` | ставится отдельно |

Наружу всё публикует nginx (`service/xuiweb.conf`), сертификат — certbot.

## Требования

- VPS с Ubuntu 24.04 (Python 3.12), доступ root, от 2 ГБ RAM и 2 vCPU.
- Домен, A-запись которого указывает на IP сервера. Порт 80 должен быть
  свободен на время выпуска сертификата.
- Токен бота от [@BotFather](https://t.me/BotFather).
- Панель **Remnawave 2.7.4** и API-токен от неё (в панели: Settings → API Tokens).

## Установка

```bash
git clone -b claude/tender-wozniak-wn8y54 https://github.com/UnionUnllimited/Xray-Panel.git /root/bot
```

```bash
cd /root/bot && bash install_bot.sh
```

Когда ветку смёржат в `main`, `-b ...` можно убрать.

Скрипт спросит:

1. **Секретный путь веб-админки** — админка будет на `https://домен/<путь>/`.
   Не оставляйте `admin123`.
2. **Домен** — под него выпускается сертификат и пишется конфиг nginx.
3. **Токен бота**.
4. **Пароль веб-админки** — Enter сгенерирует пароль и покажет его в конце.
5. **Telegram ID админа бота** (узнать у [@userinfobot](https://t.me/userinfobot)),
   несколько — через запятую.
6. **SUBPAGE** — поставить на этот сервер или указать домен внешнего.

Базу `vpn_bot.db` скрипт создаёт сам. Тексты, кнопки, ссылки на приложения
и сетка тарифов засеваются при первом старте из `service/defaults/`.

## Подключение Remnawave 2.7.4

Веб-админка → **Remnawave**:

- **Включить Remnawave** — включено по умолчанию.
- **Base URL** — адрес панели, например `https://panel.example.com`. Если панель
  на этом же сервере в docker — `http://127.0.0.1:3000` (для `http://` SDK сам
  добавляет заголовки `X-Forwarded-*`, которых ждёт панель).
- **API Token** — токен из панели.
- Сквад по умолчанию и сквад «трафик закончился» — по желанию.

Вебхуки (первое подключение, исчерпанный трафик) — в `.env` панели:

```dotenv
WEBHOOK_ENABLED=true
WEBHOOK_URL=https://<домен бота>/remnawave/webhook
WEBHOOK_SECRET_HEADER=<строка от 32 символов>
```

Ту же строку впишите в админке бота в «Секрет вебхука» и включите «Принимать
вебхуки от Remnawave». Бот проверяет подпись `X-Remnawave-Signature` этим
секретом. Домен в `WEBHOOK_URL` админка подсказывает из `connect_page_url`.

## Обновление

```bash
cd /root/bot && git pull
```

```bash
venv/bin/pip install -r service/requirements.txt && web_admin/venv/bin/pip install -r service/requirements.txt && xuiweb/venv/bin/pip install -r service/xuiweb.txt
```

```bash
systemctl restart vpn-bot vpn-webadmin xuiweb
```

После обновления PWA (новая `PWA_CACHE_VERSION` в `web_admin/routes/pwa.py`)
установленный ярлык сам подтянет свежие CSS/JS.

### Переезд с уже работающего бота

Если на сервере уже стоит этот бот со своей `vpn_bot.db`, сохраните базу,
разложите код из репозитория в `/root/bot`, верните базу на место и выполните
шаги из «Обновления». Настройки по умолчанию дописываются только
недостающими ключами: всё, что уже задано, остаётся как было.

## Что изменено относительно исходника

- **Remnawave 2.7.4.** SDK `remnawave` закреплён на 2.7.1 вместо 2.8.0.
  SDK 2.8 рассчитан на API панели 2.8: у хостов `tags` вместо `tag`,
  `xhttpExtraParams` вместо `xHttpExtraParams`, нет `allowInsecure`. Бот шлёт
  поля 2.7, и при создании хоста из шаблона они молча терялись бы. Все вызовы
  SDK и поля DTO в коде сверены с 2.7.1. Лимит трафика передаётся целым числом
  байт.
- **PWA v3.11.285** (`web_admin/routes/pwa.py`): service worker кэширует и
  `/admin-static/`.
- **Пробный период.** `trial_days=0` больше не вешает `/start` на «Активации
  на 0 дн.», а приветствие не обещает триал, которого нет.
- **Установка из git.** Готовая база больше не нужна: схема и настройки
  создаются с нуля, установщик задаёт пароль админки и ID админа.
- **Вход в админку.** Пустой пароль в базе больше не пускает с пустой формой.
- Убраны мёртвые `service/analytics.*`. Переводы строк приведены к LF:
  скрипты с CRLF на Linux не запускаются.

Инструкции вендора — в `docs/install-bot.html` и `docs/install-website.html`.

## Чего нет в репозитории

`vpn_bot.db`, `.env`, `venv/` и логи в git не попадают (`.gitignore`). Рабочая
база с клиентами и платежами живёт только на сервере: бэкапьте её отдельно.
